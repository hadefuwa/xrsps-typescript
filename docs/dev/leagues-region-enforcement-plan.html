2. How It Will Work (Architecture)

The OSRS map is divided into 64x64 chunks known as Region IDs, calculated as ((x >> 6) << 8) | (y >> 6). Rather than drawing arbitrary rectangles, we map these exact OSRS Region IDs to League Area IDs (e.g., Lumbridge's Region ID 12850 maps to Misthalin's League Area ID 1). This perfectly matches the Jagex engine architecture and handles surface and underground (dungeons) elegantly.

Enforcement occurs in two layers:

Path Request
→
continueWalkToDestination()
→
Truncates path at border of locked regions
600 ms tick
→
onPlayerTick
→
Teleport bypass catch (teleports to Edgeville)

3. Phase 1 — Build Map<osrsRegionId, leagueAreaId>

We will construct a lookup Map for the ~500–1000 OSRS Region IDs. A simple lookup function will translate any game coordinate to its League Area.

First: try extracting from cache. The region_data DB table already referenced in leagueWidgets.ts (DB column ID 335872) may contain the full OSRS Region ID → League Area ID mapping. Write a scripts/cache/dump-league-regions.ts script to dump all rows — if it works, the map populates automatically and never needs manual maintenance. Fall back to manual construction only if the data isn't there.
Because this uses exact 64x64 chunks, underground dungeons (like Revenant Caves at Y~10048) get completely distinct region IDs from the surface. This ensures that a locked dungeon surface correctly blocks the dungeon itself, with no special case logic.

Code structure

// server/gamemodes/leagues-v/leagueRegionMap.ts

/** Maps OSRS 64x64 Region ID → Leagues V Area ID. */
export const LEAGUE_REGION_MAP: ReadonlyMap<number, number> = new Map([
    // Misthalin (Area ID: 1)
    [12850, 1], // Lumbridge
    [12851, 1], // Lumbridge Swamp
    [12594, 1], // Edgeville
    // Asgarnia (Area ID: 3)
    [11828, 3], // Falador
    // ... ~500 entries
]);

export function getOsrsRegionId(x: number, y: number): number {
    return ((x >> 6) << 8) | (y >> 6);
}

export function getLeagueAreaIdForTile(x: number, y: number): number {
    const osrsRegionId = getOsrsRegionId(x, y);
    return LEAGUE_REGION_MAP.get(osrsRegionId) ?? 0;
}

4. Phase 2 — Path Truncation

To recreate the authentic OSRS feel, players walk up to the region border and stop rather than being bounced back. We post-process the BFS path result in continueWalkToDestination() — but critically, league logic must not be imported into the engine. Instead, we add one optional hook to GamemodeDefinition that the engine calls blindly. The Leagues V gamemode implements it; the vanilla gamemode ignores it.

Do not import getLeagueAreaIdForTile or isLeagueAreaUnlocked directly into PlayerManager.ts. That would couple a core engine file to a specific gamemode — the wrong dependency direction.

Step 1 — Add hook to GamemodeDefinition

// server/src/game/gamemodes/GamemodeDefinition.ts

// Add this optional method to the GamemodeDefinition interface:
filterPathSteps?(player: PlayerState, steps: { x: number; y: number }[]): { x: number; y: number }[];

Step 2 — Call the hook in PlayerManager

// server/src/game/PlayerManager.ts -> continueWalkToDestination()
// After findPathSteps() returns res.steps, before applying to actor:

const filtered = this.gamemode.filterPathSteps?.(player, res.steps) ?? res.steps;
player.setPathPreservingWalkDestination(filtered, shouldRun);

Step 3 — Implement in LeaguesVGamemode

// server/gamemodes/leagues-v/index.ts

filterPathSteps(player: PlayerState, steps: { x: number; y: number }[]): { x: number; y: number }[] {
    if (!isLeagueWorld(player) || this.isTutorialActive(player)) return steps;
    const out: { x: number; y: number }[] = [];
    for (const step of steps) {
        const areaId = getLeagueAreaIdForTile(step.x, step.y);
        if (areaId !== 0 && !isLeagueAreaUnlocked(player, areaId) && !isAlwaysAccessible(step.x, step.y)) {
            break; // stop at first locked step — player walks to border
        }
        out.push(step);
    }
    return out;
}

5. Phase 3 — Teleport-Back in onPlayerTick()

Path truncation prevents walking into locked regions, but players can still bypass paths via teleports, portals, or rubbing amulets. The onPlayerTick logic acts as a safety net: if a player lands in a locked region, bounce them to Edgeville. Edgeville is always safe to use as the fallback because it sits inside Misthalin — the region every player has unlocked by default.

// server/gamemodes/leagues-v/index.ts

const HOME_LOCATION = { x: 3087, y: 3492, level: 0 }; // Edgeville bank
private regionEnforcementCooldown = new Map<number, number>();

private enforceRegionAccess(player: PlayerState, currentTick: number): void {
    if (!isLeagueWorld(player) || this.isTutorialActive(player)) return;

    const { tileX, tileY } = player;

    if (isAlwaysAccessible(tileX, tileY)) return;

    const areaId = getLeagueAreaIdForTile(tileX, tileY);
    if (areaId === 0) return; // unmapped tile (instances, sea, etc.) — allow

    if (isLeagueAreaUnlocked(player, areaId)) return;

    const lastTick = this.regionEnforcementCooldown.get(player.id) ?? -99;
    if (currentTick - lastTick < 5) return; // debounce teleports

    this.regionEnforcementCooldown.set(player.id, currentTick);
    player.teleport(HOME_LOCATION.x, HOME_LOCATION.y, HOME_LOCATION.level);
    // services.chat.sendMessage(player, "You have not unlocked this region.");
}

6. Phase 4 — Client Map Graying (Out of Scope)

Graying out locked regions on the minimap and world map requires sending the unlock state to the client and hooking into the map rendering. Since the world map widget is driven by CS2 scripts in the cache, this is a separate, larger task that is out of scope for the current region enforcement.

7. Always-Accessible Zones

Some areas are accessible globally, independent of Region IDs.

ZoneTile rangeWhy always accessible
Tutorial island (3088, 3096) → (3100, 3112) Leagues tutorial spawn — outside all league region bounds
Edgeville (home) Misthalin — always unlocked Fallback destination. No special exemption needed; covered by Misthalin (Area 1) being the default unlock
Instances player.isInInstance() == true Dynamic instances should not be blocked
Unmapped regions areaId === 0 Safe default — don't punish players for missing map definitions 
export function isAlwaysAccessible(x: number, y: number): boolean {
    // Tutorial island spawn (outside normal league region bounds)
    if (x >= 3088 && x <= 3100 && y >= 3096 && y <= 3112) return true;
    return false;
    // Note: Edgeville is in Misthalin (always unlocked) — no exemption needed.
}

9. Edge Cases to Handle

✅ Edgeville as home — no special exemption needed

Edgeville sits inside Misthalin (Area 1), which is the region every player has unlocked by default. Unlike Ferox Enclave (which was inside the Wilderness), Edgeville passes the normal region check naturally — no entry in isAlwaysAccessible is required.

⚠️ Agility Shortcuts & Forced Movements

Agility shortcuts bypass continueWalkToDestination() pathfinding. If an agility shortcut connects an unlocked area to a locked area, the player will land in the locked area and immediately be scooped up by the onPlayerTick teleport fallback. This is the desired safe behavior.
